# Stitch 生成 prompt 模板与范例(references)

本文件是 `vibe-prototype` 第 2 步「为每页撰写 Stitch 生成 prompt」的细节支撑:固定结构模板、shadcn / Radix 美学要求、一个填好的真实范例。

每页一段 prompt,由 Claude 依据 `design.md`(视觉准则,视觉权威)+ `interaction.md`(元素 / 状态)合成(数据 / 接口依据见 `architecture.md`),写入 `prototypes/prompts/<页面ID>.md`,供用户复制进 Stitch 画布。页面ID 必须与 interaction.md 逐字符一致(kebab slug)。原型视觉**必须符合 design.md** 的 tokens / components / Do&Don't。

## Stitch prompt 固定结构模板

把下面七要素逐项填实(尖括号示意槽仅为模板提示,产出时必须替换成具体内容,不得留空):

### ① 页面标题与用途

取自 interaction.md 的页面定位:这页叫什么、给谁用、解决什么核心任务、在流程里的位置。

### ② 设计系统约束(视觉权威)

**取自 design.md(视觉准则)** 的 token 前言 / Colors / Typography / Layout / Elevation / Shapes / Components / Do&Don't,逐项写出(原型视觉**必须符合 design.md**):

- 主色 / 辅色(具体色值或语义角色,取自 design.md tokens);
- 字体家族(标题 / 正文,取自 design.md Typography);
- 圆角(统一 radius,取自 design.md Shapes);
- 间距基准(基础间距刻度,取自 design.md Layout);
- 组件风格(卡片 / 按钮 / 表单的整体观感,取自 design.md Components);
- Do&Don't(把 design.md 的 Don't 写成禁止项、Do 写成要求项)。

### ③ shadcn / Radix 美学对齐(强制)

见下文「shadcn / Radix 美学要求」,**每段 prompt 必须原样写入这四点约束**。

### ④ 布局描述

顶 / 侧 / 内容 / 底各区块,以及栅格结构(列数、断点、主次区域占比)。

### ⑤ 关键元素逐条列举

每个按钮、输入框、列表项逐条列出,并写明**文案**(按钮文字、输入框提示语 placeholder、标签、列表字段名)。

### ⑥ 交互态提示

标明哪些元素点击后是**弹窗 / 全屏跳转 / 浮窗 / 侧滑抽屉 / toast**。静态原型里尽量以「展开态 / 弹窗态」表达,或**拆成 `<页面ID>` 与 `<页面ID>--<子态名>` 两张图**(双连字符)。

### ⑦ 空态 / 加载态 / 错误态

若 interaction.md 标注了页面级四态,则要求一并出图(空态文案与引导、加载骨架、错误提示与重试)。

## shadcn / Radix 美学要求(每段 prompt 强制写入)

在 ② 设计系统约束里,**每段 prompt 都必须明确写入**「设计系统贴近 shadcn / Radix 美学」,落地为四点:

- **中性色板**:以 neutral/slate 基调为主,强调色克制使用;
- **克制圆角**:统一一个 radius,不夸张、不到处不同;
- **清晰的层级与对比**:信息层级分明、文本对比充足;
- **systemic spacing**:基于统一间距刻度的留白,而非随手填值。

**目的**:让 Stitch 原型从一开始就接近最终 shadcn 实现的视觉语言,最大限度减少「原型一套风格、代码另一套风格」带来的视觉改写成本。

## 填好的范例:`order-list`(订单列表页)

> 下面整段可直接复制进 Stitch 画布生成主图;末尾给出一个子态 `order-list--filter-drawer` 与空态 / 加载态的补充 prompt。

```
【页面标题与用途】
订单列表页(order-list)。面向已登录的商家用户,用于浏览、筛选、检索全部订单,并进入单个订单详情处理发货 / 退款。是商家工作台进入后的默认首屏之一。

【设计系统约束】
- 主色:靛蓝(primary),用于主操作按钮与选中态;辅色:中性灰阶用于背景与分隔。
- 字体家族:标题与正文同一无衬线家族(如 Inter),标题字重 600、正文 400。
- 圆角:统一 radius 0.5rem(卡片、按钮、输入框一致)。
- 间距基准:4px 刻度(8 / 12 / 16 / 24)。
- 组件风格:卡片化列表 + 顶部工具条,克制阴影。

【shadcn / Radix 美学对齐(强制)】
设计系统贴近 shadcn / Radix 美学:中性色板(neutral/slate 基调,强调色克制),克制的圆角(统一 radius,不夸张),清晰的层级与对比(标题/正文/次要信息层级分明、文本对比充足),systemic spacing(基于统一间距刻度的留白)。

【布局描述】
- 顶部:页面标题「订单」+ 右侧主操作按钮「导出」。
- 工具条(标题下一行):搜索框 + 状态筛选 Tabs(全部 / 待付款 / 待发货 / 已完成 / 已退款)+ 右侧「筛选」按钮。
- 内容区:订单卡片列表(单列,移动端);桌面端 12 栅格,列表占满,卡片间距 16。
- 底部:分页器(上一页 / 页码 / 下一页)。

【关键元素逐条列举】
- 搜索框:提示语「搜索订单号 / 收货人」。
- 状态筛选 Tabs:全部 / 待付款 / 待发货 / 已完成 / 已退款。
- 「筛选」按钮:文案「筛选」,点击打开侧滑抽屉(见子态)。
- 「导出」按钮:文案「导出」(次要按钮样式)。
- 订单卡片(列表项,每项含):订单号、下单时间、收货人、金额、状态标签(Badge)、右侧「查看详情」链接按钮。
- 分页器:上一页 / 当前页码 / 下一页。

【交互态提示】
- 点击「筛选」→ 侧滑抽屉(drawer):拆为子图 order-list--filter-drawer。
- 点击订单卡片「查看详情」→ 全屏跳转到 order-detail(本图不画详情)。
- 导出成功 → toast 提示(本图以静态主态表达,不单独出图)。

【空态 / 加载态 / 错误态】
- 空态:无订单时,列表区居中显示插画 + 文案「还没有订单」+ 次要说明。
- 加载态:首次加载显示 3~5 张卡片骨架屏(skeleton)。
- 错误态:加载失败显示错误文案「订单加载失败」+「重试」按钮。
```

### 子态范例:`order-list--filter-drawer`(侧滑抽屉)

```
【页面标题与用途】
订单列表页的筛选侧滑抽屉(order-list--filter-drawer)。从 order-list 点击「筛选」后右侧滑出。

【shadcn / Radix 美学对齐(强制)】
同 order-list:中性色板(neutral/slate 基调)、克制圆角(统一 radius)、清晰层级与对比、systemic spacing。

【布局描述】
右侧滑出抽屉,宽约 360px,顶部标题「筛选」+ 关闭按钮,内容为分组表单,底部固定「重置 / 应用」两按钮。

【关键元素逐条列举】
- 下单时间范围:日期区间选择器。
- 金额范围:最小值 / 最大值两个输入框。
- 订单来源:多选(小程序 / H5 / App)。
- 底部:「重置」(次要按钮)/「应用」(主按钮)。
```

> 范例与第 5 步对齐:`order-list` 主图覆盖 interaction.md 的元素清单(搜索、Tabs、卡片字段、分页),`order-list--filter-drawer` 子态对应抽屉触发点,空态 / 加载态 / 错误态对应页面级四态——这样原型才能在三铁律「元素一致」上对得上文档。
